# P0 执行计划

## 目标

把 EventRush 从“混合展示台”改成“票务产品主入口 + 独立工程证据入口”。

## P0 范围

### 必须做

1. 票务前台。
2. 电子票查询。
3. 验票入口。
4. 工程证据入口。
5. 退票、通知、异常状态的产品边界预留。

### 现在不做

1. 主办方完整控制台。
2. 复杂权限系统。
3. 座位图。
4. 监控大屏。
5. 真实支付网关。

## 角色分层

### 普通用户

只看这些：

- 活动。
- 场次。
- 票档和库存。
- 下单。
- 支付。
- 电子票。
- 退票入口。
- 通知入口。

### 工作人员

只看这些：

- 票码。
- 票状态。
- 验票结果。
- 重复验票提示。

### 工程与运营

只看这些：

- traceId。
- 最近请求。
- 压测结果。
- 是否超卖。
- 管理查询。

## 页面规则

### 默认首屏

默认首屏必须是票务前台，不是压测、不是真实证据、不是真正后台。

### 入口分离

不同角色必须分入口，不要混在同一页里。

### 工程证据

工程证据必须独立收纳，不能打断用户购票路径。

## 执行顺序

1. 先把购票主流程做顺。
2. 再把电子票和验票拆开。
3. 再把工程证据单独收口。
4. 最后再补主办方能力。

## 成功标准

P0 结束时，必须满足：

- 用户打开页面时，先看到票务主流程。
- 工程证据不再抢占默认首屏。
- 验票是独立入口，不混在购票页。
- `traceId` 只出现在工程入口和必要的排查位置。
- 每个入口都能单独成功，不依赖另一个入口凑页面完整。

## 失败判定

如果出现下面任一情况，P0 不算成功：

- 默认首屏仍然是工程输出。
- 一个入口同时承担多个角色。
- 购票流程被压测和排查打断。
- 验票和购票混成一页。
- 只有“能跑通”，没有“角色边界”。

## 一句话

P0 不是把页面变多，而是先把产品变对。
