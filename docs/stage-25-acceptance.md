# 第 25 阶段验收：项目阶段总览

## 本阶段交付

- 新增项目阶段总览文档：`docs/stage-overview.md`。
- 把第 1 到第 24 阶段整理成一张总表。
- 按业务主线、防超卖和幂等、Redis 和 Lua、RocketMQ 和异步、接口治理、压测和项目表达做主题归类。
- 在 `README.md` 和 `docs/learning-map.md` 中补充总览入口。

## 为什么要做这一阶段

项目已经推进到 Redis Lua、RocketMQ、压测报告和接口治理之后，内容开始变多。这个阶段不是继续堆功能，而是帮你真正接收成果。

这一阶段要解决的问题是：

- 你能不能说清楚每个阶段为什么做。
- 你能不能把零散功能串成完整业务链路。
- 你能不能按主题复习库存、幂等、MQ、Redis、接口治理和压测。
- 你能不能用 1 分钟讲清楚这个项目。

## 自动验收

在项目根目录执行：

```powershell
mvn test
```

预期结果：

- 测试全部通过。
- 文档变更不影响业务代码。

## 手动验收

打开：

```text
docs/stage-overview.md
```

检查以下内容：

- 是否覆盖第 1 到第 24 阶段。
- 是否能看出每一阶段的主题、交付成果和学习点。
- 是否按主题归类业务、库存、幂等、Redis、RocketMQ、接口治理和压测。
- 是否提供了 1 分钟项目介绍版本。
- README 和学习地图是否能找到入口。

## 你需要学会的点

- 项目复盘要按“业务链路”和“技术主题”两条线同时整理。
- 面试表达不能只说“我用了 Redis/RocketMQ”，要说清楚它们解决了什么业务问题。
- 阶段总览能帮助你从“我跟着做完了”升级到“我能自己讲清楚”。
- 真正接收成果，不是记住文件名，而是能把每个阶段放回完整链路里。

## 面试表达

可以这样说：

> 我给项目整理了阶段总览，把第 1 到第 24 阶段按业务链路和技术主题重新归类。这样我不只是知道项目里用了 Redis、RocketMQ、Lua、统一响应和压测脚本，还能说清楚每一步解决的具体问题：比如抢票防超卖、重复请求幂等、延时消息取消订单、traceId 排查问题，以及如何用压测报告验证优化效果。

## 下一阶段建议

第 26 阶段建议做“项目复盘问答训练”：把库存、幂等、MQ、Redis Lua、压测和接口治理整理成面试问答。
