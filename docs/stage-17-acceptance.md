# 第 17 阶段验收：中文 API 文档整理

## 本阶段交付

- 新增当前项目 API 总文档：`docs/api-reference.md`。
- 按普通用户接口和管理端接口分类整理。
- 补充统一响应格式、`traceId`、错误码、管理端密钥规则。
- 补充核心对象字段说明：活动、场次、票档、订单、电子票。
- 新增 HTTP 验收文件：`requests/stage-17.http`。

## 为什么要做这一阶段

前 16 个阶段已经完成了不少能力：活动查询、抢票、异步抢票、支付出票、订单超时、验票、统一响应、链路追踪、后台查询和后台密钥保护。

如果只有代码，没有接口文档，你后面复习和展示项目时会很费劲。第 17 阶段的目标是把“项目已经能做什么”整理成一份可以讲、可以查、可以验收的中文材料。

## 自动验收

在项目根目录执行：

```powershell
mvn test
```

预期结果：

- 测试全部通过。
- 文档整理没有影响现有业务代码。
- 管理端鉴权测试仍然通过。

## 手动验收

打开文档：

```text
docs/api-reference.md
```

检查以下内容：

- 是否能看到统一响应格式。
- 是否能看到 `X-Trace-Id` 和 `X-Admin-Key` 的说明。
- 是否能区分普通用户接口和管理端接口。
- 是否能看到每个接口的路径、请求体和用途。
- 是否能看到订单状态、电子票状态等核心字段说明。

也可以使用：

```text
requests/stage-17.http
```

按顺序执行接口，完成一条从“查询活动 -> 抢票 -> 支付 -> 查票 -> 验票 -> 管理端查询”的链路。

## 你需要学会的点

- 写 API 文档时，先写通用规则，再写具体接口。
- 接口文档要面向使用者，不只是面向写代码的人。
- 一份好的接口文档应该能帮助别人快速完成一次完整业务验收。
- 项目展示时，你可以先讲业务链路，再拿接口文档证明每一步都有对应接口。

## 面试表达

可以这样说：

> 我把项目接口整理成了一份中文 API 文档，按用户端和管理端分类，补充了统一响应结构、traceId、管理端鉴权请求头、错误码和核心数据对象字段。这样项目不仅有代码实现，也有可复习、可联调、可展示的接口材料。
