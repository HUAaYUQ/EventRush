# Stage 46 验收：可恢复交易闭环

## 做了什么

- 票档增加价格，订单持久化单价快照和应付金额。
- “我的电子票”升级为订单中心，支持刷新后找回待支付订单和电子票。
- 待支付订单显示倒计时，过期支付会明确取消并释放库存。
- 修复取消后仍被数据库唯一约束阻止再次购买的问题。
- 细分重复购买、售罄、订单过期、订单不存在和重复验票等错误码。

## 你该学会什么

1. 订单要保存价格快照，不能只在页面临时计算。
2. 防重复购买应该约束“有效订单”，取消订单不能永久占用购买资格。
3. 支付截止时间既是页面提示，也是后端必须再次校验的业务规则。
4. 错误码的价值是让前端决定恢复动作，而不是只把错误文字显示出来。

## 怎么验收

1. 打开“车票预订”，确认票档显示价格、余票和中文场次信息。
2. 抢票后确认订单显示金额及支付倒计时。
3. 刷新页面并打开“我的电子票”，确认订单仍能通过本机演示用户找回。
4. 对待支付订单点击“继续支付”，支付后自动进入订单中心。
5. 对已支付订单点击“查看电子票”，确认取回同一个 `ticketCode`。
6. 自动化测试确认过期订单会取消，且同一用户可以重新购买同一票档。

## 当前边界

- 当前订单固定为 1 张，还没有购票数量和实名购票人模型。
- 本机演示用户只用于稳定恢复页面状态，不等同于正式登录认证。
- 工程证据仍是下一阶段重点，本阶段没有把手填数据包装成真实压测结果。
