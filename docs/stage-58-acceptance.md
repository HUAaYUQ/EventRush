# Stage 58：类型化活动详情发布

## 做了什么

- 活动类目新增内容模板：演出、赛事、展览、亲子和通用。
- 发布活动重组为商品定位、场次售票、购票与入场规则、详情内容、预览发布五步。
- 购票与入场规则按模板生成稳定字段，主办方必须逐项填写真实内容。
- 详情支持图文介绍、活动亮点、阵容、详情图片、交通和重要说明，可新增、删除和排序。
- 已有活动新增“详情与规则”页签，保存只更新草稿，再次发布后才替换公开版本。
- 购票详情页根据活动类型显示演出介绍、赛事介绍、观演须知、观赛须知或活动须知，并按后台顺序展示详情模块。

## 你该学会什么

1. 类目可以同时承担检索分类和内容治理职责，但模板只定义必填结构，不应写死业务文案。
2. 活动基础信息、规则、详情模块和场次票档共同组成一次发布，不能由前端各自随意拼接。
3. 草稿表保存编辑状态，发布表保存用户可见快照；公开查询只读取发布表。
4. 不同活动需要不同的须知和介绍标题，但后台仍应使用统一的数据结构和校验方式。
5. 详情图片必须走平台上传和公开地址，不能依赖外部占位图或前端临时素材。

## 怎么验收

1. 打开 `/organizer/settings/categories`，确认类目可以选择演出、赛事、展览、亲子或通用模板。
2. 打开 `/organizer/events/new`，确认发布流程为五步，第二步同时配置销售周期、首场次和首票档。
3. 在第三步切换“购票须知”和“入场须知”，确认字段随类目模板变化且空内容不能继续。
4. 在第四步新增多个详情模块，完成排序并上传详情图片，确认发布检查能识别完整状态。
5. 发布后打开 `/events/:eventId`，确认标题、规则分组、详情顺序和图片与后台一致。
6. 回到活动的“详情与规则”，修改内容并保存但不发布，确认购票端仍展示旧版本；点击“发布最新版本”后再确认切换。
7. 执行 `mvn test` 和 `frontend` 目录下的 `npm.cmd run build`，两项必须通过。

## 自动验证范围

- 后端接口测试覆盖类目模板、规则与详情保存、首次发布、草稿隔离和再次发布切换。
- 前端生产构建覆盖主办方规则编辑器、详情编排器和购票端公开详情渲染。
- 桌面与 320、375、414、768 像素视口用于检查发布台和活动详情页的布局、触控区域与文字换行。
