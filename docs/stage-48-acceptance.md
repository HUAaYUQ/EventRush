# Stage 48 验收：多人订单与独立电子票

## 做了什么

- 一笔订单支持 1 到 5 位购票人，订单数量由购票人清单自动推导。
- 库存扣减、Redis Lua 预扣减和超时释放都按实际人数执行。
- 订单增加独立的购票人明细表，历史 H2 订单启动时会自动补成一位购票人。
- 支付后为每位购票人生成独立 `ticketCode`，重复支付返回原有票列表，不重复出票。
- 每张电子票绑定具体购票人，验票只更新当前票码，不影响同订单其他人的票。
- 前端支持添加、移除和核对购票人，并按订单展示多张电子票。

## 你该学会什么

1. 订单是一次交易，电子票是个人入场凭证，所以两者应是一对多关系。
2. `quantity` 不能让前端自由填写，应由购票人列表长度推导，避免人数、金额和库存不一致。
3. 多人订单的扣库存、取消释放、支付出票必须使用同一个数量口径。
4. 支付幂等不只是防止订单重复变成已支付，还要防止部分或全部电子票重复生成。

## 怎么验收

1. 打开“车票预订”，选择标准票并添加第二位购票人。
2. 分别填写两人的姓名、证件类型和证件后四位，点击“核对订单”。
3. 确认票数为 `2 张`，应付金额等于票价乘以 2，且右侧逐人显示票的对应关系。
4. 提交订单并支付，确认页面生成两张不同的电子票码。
5. 进入“我的电子票”，确认同一订单下两位购票人各有一张票。
6. 复制第一张票码进入“验票入口”完成核验，确认第一张变为“已入场”。
7. 查询第二张票，确认仍为“待入场”，证明验票状态相互独立。
8. 对同一订单再次调用支付，确认仍返回原来的两张票码。

## 当前边界

- 每笔订单最多 5 位购票人，属于当前演示产品的明确限制。
- 项目只保存证件类型和后四位，不能据此做真实身份去重。
- 当前没有座位号和选座能力，多张票共享同一活动、场次和票档。
- 支付后退票、部分退票和票码失效将在后续阶段实现。
