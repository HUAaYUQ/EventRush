# 第 43 阶段验收：工作台规格定义

## 目标

在正式重构 UI 前，先把 EventRush 前端工作台定义清楚：它围着什么对象转、首屏要证明什么、模块怎么排、数据从哪里来、哪些内容暂不做。

## 交付

| 文件 | 说明 |
| --- | --- |
| `.workbench/spec.md` | 新增工作台规格，作为后续 UI 调整依据 |
| `docs/stage-43-acceptance.md` | 本阶段验收说明 |

## 验收结果

| 检查项 | 结果 |
| --- | --- |
| 主对象 | 已明确为“票务订单” |
| 首屏结论 | 已绑定订单状态、电子票状态、最近失败请求 |
| 模块范围 | 已收敛为票务链路、验票、管理排查、请求记录、压测证据 |
| 数据来源 | 已写明系统写入、用户输入和暂未接入的数据 |
| 暂不做 | 已明确排除营销首页、复杂登录、座位图、真实支付和监控大屏 |

## 本阶段边界

本阶段只定义工作台规格，不改前端页面代码。下一阶段再按规格调整 UI 结构和交互。

## 你需要学会的点

- UI 不是先画卡片，而是先确定它要证明什么。
- 首屏不能只放总数，必须能指向一条可操作、可排查的链路。
- 每个展示数字都要能说清楚由谁写入、什么时候写入。
