# 第 36 阶段验收：支付出票链路

## 本阶段目标

本阶段在前端工作台中实现用户端主链路的第二步：基于已创建的待支付订单完成支付，并展示电子票。

这一阶段要让你明确看到：

- 抢票成功后只是 `PENDING_PAYMENT` 订单。
- 点击支付后调用支付接口。
- 支付成功后生成电子票。
- 电子票状态为 `VALID`。
- 订单状态刷新为 `PAID`。

## 已完成能力

### 1. 支付订单

页面会基于当前 `orderId` 调用：

```http
POST /api/orders/{orderId}/pay
```

成功后展示：

- `ticketCode`
- 票状态
- 关联 `orderId`
- 支付接口 `traceId`

### 2. 刷新订单状态

支付成功后，前端会继续调用：

```http
GET /api/orders/{orderId}
```

用于把页面上的订单状态从 `PENDING_PAYMENT` 刷新成 `PAID`。

### 3. 支付幂等展示基础

当前后端支付接口具备幂等能力：同一个订单重复支付会返回同一张电子票。

第一版前端保留“支付并出票”按钮，后续可以继续补一条重复支付验收提示。

7. 确认页面出现 `ticketCode`。
8. 确认电子票状态为 `VALID`。
9. 确认订单状态刷新为 `PAID`。

## 本阶段边界

本阶段暂不做：

- 输入票码查询电子票。
- 验票。
- 重复支付的专门提示。
- 管理端查询。
- 最近请求记录。

这些会在后续阶段继续补齐。

## 你需要学会的点

- 抢票成功和出票成功是两个不同阶段。
- 订单负责交易状态，电子票负责入场凭证。
- 支付成功后才生成 `ticketCode`。
- 前端展示订单状态时，要在支付后刷新，避免页面停留在旧状态。
- 支付接口幂等的含义是重复支付不会生成多张票。
