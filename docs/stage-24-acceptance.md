# 第 24 阶段验收：Redis Lua 压测开关说明

## 本阶段交付

- 新增 Redis Lua 压测开关说明：`docs/redis-lua-pressure-switch.md`。
- 说明如何开启 `eventrush.stock.redis-enabled=true`。
- 说明 Redis Lua 脚本在抢票链路中的作用。
- 说明默认方案和 Redis Lua 方案如何用同参数对比。
- 在 `README.md`、`docs/learning-map.md`、`docs/pressure-test-guide.md` 中补充入口。

## 为什么要做这一阶段

第 22 阶段解决“怎么跑压测”，第 23 阶段解决“怎么写报告”。第 24 阶段补上“怎么开启 Redis Lua 方案做对比”。

这一阶段要让你清楚：

- Redis 库存扣减不是默认开启。
- 开启 Redis 前要先保证 Redis 可用。
- 开启后应用会预加载票档库存。
- 对比压测必须使用相同参数。
- 本地压测只能作为学习基线，不代表生产性能。

## 你需要学会的点

- Redis Lua 的价值是把多步 Redis 操作合成一次原子执行。
- 做优化对比时，参数必须一致，否则对比没有意义。
- 开关能力要写清楚默认值、开启方式、依赖条件和风险。
- 本地压测数据只能当学习证据，不能包装成生产性能。

## 面试表达

可以这样说：

> 我给 Redis Lua 抢票方案整理了压测开关说明。默认情况下项目不依赖 Redis，开启 `eventrush.stock.redis-enabled=true` 后，应用会预加载票档库存，抢票时先通过 Lua 脚本原子完成库存检查、重复用户检查和库存扣减。压测时用同一组并发用户、票档和用户 ID 范围对比默认方案和 Redis Lua 方案，重点看是否超卖、失败是否符合预期，以及 QPS、P95、P99 的变化。
