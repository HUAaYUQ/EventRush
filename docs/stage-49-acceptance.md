# Stage 49：部分退票与整单退票验收

## 做了什么

- 新增用户订单退票接口，可一次选择 1 到 5 张电子票。
- 支持多人订单只退其中一人，订单进入 `PARTIALLY_REFUNDED`。
- 全部电子票退完后订单进入 `REFUNDED`，并恢复同票档购买资格。
- 退款金额按订单单价乘以本次实际新退票数量计算，当前手续费为 0。
- 重复提交已退票码不会重复退款，也不会重复释放库存。
- 已验票凭证和场次开始后的凭证不能在线退票。
- 前端提供逐票选择、退款明细、后果确认、成功回执和全退后重新购买。

## 你该学会什么

1. 部分退票不是只改订单状态，还要同步维护单票状态、累计退款金额、库存和重复购买标记。
2. `PARTIALLY_REFUNDED` 仍占用本次购买资格；只有 `REFUNDED` 才清除 `active_grab_key`。
3. 幂等要以“本次实际新退了几张”为准，已退票码再次请求时新增退款金额必须为 0。
4. 已验票和已退票都是电子票终态，不能再次进入另一条售后或验票路径。
5. 高风险操作的前端要在提交前展示后果和金额，提交后保留页面级回执，不能只弹一个短暂提示。

## 产品验收

1. 启动后端和前端，进入“车票预订”。
2. 选择两位购票人，下单并支付，记录订单金额、库存和两张 `ticketCode`。
3. 进入“我的电子票”，打开该订单，只勾选第一张 `VALID` 票。
4. 核对页面显示“票面价 × 1、手续费 ¥0.00、预计退款一张票价”。
5. 提交退票，确认弹窗明确提示票码立即失效、不能入场和退款金额。
6. 成功后确认订单为 `PARTIALLY_REFUNDED`，第一张票为 `REFUNDED`，第二张仍为 `VALID`。
7. 刷新活动，确认库存只恢复 1；刷新订单，确认累计退款金额等于一张票价。
8. 使用接口重复提交第一张票码，确认 `newlyRefundedQuantity = 0`、`newlyRefundedAmountCents = 0`，库存不再变化。
9. 对第二张票先执行验票，再尝试退票，确认返回 `TICKET_NOT_REFUNDABLE`，订单仍为部分退票。
10. 新建另一笔多人订单，将全部电子票退完，确认订单为 `REFUNDED`。
11. 点击“重新购买同票档”，确认同一用户可以再次下单。

## 接口示例

```http
POST /api/users/{userId}/orders/{orderId}/refunds
Content-Type: application/json

{
  "ticketCodes": ["ER-第一张票码"]
}
```

## 验收结论

通过标准：部分退一人只退一张票价并只恢复 1 个库存；另一张票仍可入场；重复退票不重复退款；已验票不可退；全部退完后订单为 `REFUNDED` 且允许重新购买。
