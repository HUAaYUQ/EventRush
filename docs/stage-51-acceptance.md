# Stage 51 验收：多角色产品边界与独立入口

## 做了什么

- 引入 Vue Router，把原来单页顶部的四类能力改成可刷新、可直达的独立网址。
- 购票前台只保留“活动票预订”和“我的订单与票”，不再向消费者展示验票、运营和压测入口。
- `/gate` 只承载票码查询与入场核销，`/ops` 只承载请求记录和管理排查，`/lab` 只承载验收摘要与压测对比。
- 新增 `/demo` 身份入口，用于成果接收和面试演示，不承载具体业务操作。
- 保留现有订单、候补、电子票、退票、traceId 和压测状态，避免产品拆分破坏已完成链路。

## 你该学会什么

1. “换网址”只是表现，真正的产品拆分要同时明确使用者、核心任务、可见数据和禁止出现的能力。
2. 12306 值得借鉴的是任务分区、订单恢复和候补心智，不是把活动票务改成铁路术语。
3. 购票、验票、平台运营和工程实验的使用频率与风险不同，不能依靠同一组顶部标签充当权限边界。
4. 先用正式路由建立稳定边界，再逐步拆组件和接入登录权限，比一次重写整个前端更容易验证。

## 页面验收

1. 打开 `/demo`，确认可以看到五个任务入口，但页面本身没有购票、验票或管理表单。
2. 打开 `/` 和 `/my`，确认顶部只出现“活动票预订”和“我的订单与票”。
3. 打开 `/gate`，确认只显示验票任务，看不到购票、管理排查和压测录入。
4. 打开 `/ops`，确认能查看请求记录和管理端反查，看不到压测表单。
5. 打开 `/lab`，确认能查看压测与方案对比，看不到管理端密钥和订单反查按钮。
6. 分别在这些网址刷新浏览器，确认仍停留在原身份页面。
7. 用 320、375、414、768 和 1365 像素宽度检查页面，确认没有横向溢出或按钮文字挤压。

## 面试表达

> 我先把高并发票务的业务闭环做完整，再把同一套数据按角色拆成独立产品入口。购票用户关注交易恢复，验票员关注快速核销，平台运营通过 traceId 和业务编号排查，工程实验室才展示压测证据。这样既能参考 12306 的任务分区，也不会把面试证据误做成消费者功能。
