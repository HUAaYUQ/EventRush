# 第 20 阶段验收：项目学习地图

## 本阶段交付

- 新增项目学习地图：`docs/learning-map.md`。
- 按知识点整理项目代码入口、测试入口、文档入口和面试表达。
- 覆盖业务主线、库存一致性、Redis、订单状态机、幂等、RocketMQ、接口治理、文档验收。
- 在 `README.md` 中补充学习地图入口。

## 为什么要做这一阶段

前 19 个阶段已经让项目能运行、能验收、能展示。但你真正要从项目里学到东西，还需要知道：

- 学 Redis 时看哪里。
- 学 MQ 时看哪里。
- 学幂等时看哪里。
- 学订单状态机时看哪里。
- 学接口治理时看哪里。
- 面试时每个点怎么表达。

学习地图就是把“代码文件”和“知识点”连接起来，避免你只知道项目做过很多事，却不知道复习时从哪里下手。

## 自动验收

在项目根目录执行：

```powershell
mvn test
```

预期结果：

- 测试全部通过。
- 新增文档不影响业务代码。

## 手动验收

打开：

```text
docs/learning-map.md
```

检查以下内容：

- 是否能按知识点找到对应代码文件。
- 是否能按知识点找到对应测试文件。
- 是否能看到每个知识点的面试表达。
- 是否有最小复习清单。
- 是否有自测问题。

## 你需要学会的点

- 项目学习不能只按文件夹看，要按知识点看。
- 面试讲项目时，不是背代码，而是讲“问题 -> 设计 -> 实现 -> 验证”。
- 一个复杂项目要能拆成几个可讲清楚的主题：库存、订单、幂等、MQ、接口治理。
- 学习地图能帮你从“我做过”变成“我讲得清楚”。

## 面试表达

可以这样说：

> 我给项目整理了一份学习地图，把每个后端知识点对应到具体代码、测试和文档。比如 Redis 对应库存 Lua 和限流 Lua，MQ 对应异步抢票和订单超时取消，幂等对应支付、验票和消息消费。这样复习和讲项目时，可以按知识点展开，而不是零散地介绍文件。
