# Stage 57：演出商品化与可视化配置

## 做了什么

- 活动从“名称、地点、封面”扩展为完整票务商品：类目、城市、场馆、地址、销售周期、演出时长、限购、实名、入场、退票和候补规则。
- 新增活动公开快照。活动信息、场次时间和票档名称与价格保存后只更新编辑稿，再次发布后购票端才切换版本；实时库存不冻结。
- 主办方中心拆出活动项目、发布活动、首页内容、类目管理四个工作区。
- 发布活动改为商品信息、销售规则、场次、票档与库存、发布检查五步流程。
- 活动封面和首页主视觉均通过后台上传；购票端不再依赖硬编码示例图片。
- 购票首页按后台类目、城市、日期和销售状态浏览，详情页展示完整票务规则。
- 正式默认启动不注入示例活动，测试环境通过配置显式开启测试数据。

## 你该学会什么

1. 活动、场次和票档的职责不同：活动是商品，场次是履约时间，票档是价格与库存单元。
2. 后台“保存”和“发布”不能等价。草稿用于编辑，公开快照用于稳定服务用户。
3. 类目、首页内容和活动规则都属于平台配置，不能散落为前端常量。
4. 售罄候补必须由活动规则开启，前端入口和后端校验都要服从同一配置。
5. 正式空状态是产品状态，不应该靠示例数据掩盖后台尚未发布内容的事实。

## 怎么验收

1. 启动后端和前端，打开 `/`，确认没有后台发布内容时显示“活动尚未上架”，但类目导航正常加载。
2. 打开 `/organizer/settings/categories`，创建或停用类目，确认购票首页只显示启用类目。
3. 打开 `/organizer/events/new`，确认五步发布流程包含完整商品、销售和观演规则，封面只能通过后台上传。
4. 完成活动、场次和票档并发布，确认活动出现在购票端，详情字段与后台一致。
5. 修改已发布活动但不再次发布，确认购票端仍显示旧版本；点击“发布最新版本”后再确认切换。
6. 打开 `/organizer/content`，进入活动的首页内容配置，确认保存草稿不会替换线上主视觉，发布后才生效。
7. 执行 `mvn test` 和 `frontend` 目录下的 `npm.cmd run build`，两项必须通过。

- 视觉：桌面与移动视口检查了正式空首页、类目管理和五步活动发布页。
