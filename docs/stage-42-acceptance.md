# 第 42 阶段验收：最近请求记录

## 本阶段目标

本阶段在前端工作台中加入最近请求记录，让每次接口调用的动作、接口、结果、code 和 traceId 都能在页面上看到。

这一阶段要让你明确看到：

- 前端不是只展示最终结果，也能保留接口调用痕迹。
- 成功和失败请求都应该能被记录。
- traceId 是排查一次请求的关键线索。
- 最近请求记录能辅助你演示统一响应、错误处理和后台排查能力。

## 已完成能力

### 1. 最近 8 条请求记录

页面会保留最近 8 条接口请求记录。

记录字段：

| 字段 | 含义 |
| --- | --- |
| 时间 | 请求发生时间 |
| 动作 | 例如加载活动、同步抢票、支付出票 |
| 接口 | 请求方法和路径 |
| 结果 | 成功或失败 |
| code | 后端统一响应里的业务 code |
| traceId | 后端返回的链路 ID |
| 摘要 | 例如 `orderId`、`ticketCode`、状态或错误信息 |

### 2. 成功请求记录

例如：

- 加载活动成功，记录活动数量。
- 同步抢票成功，记录 `orderId` 和订单状态。
- 支付出票成功，记录 `ticketCode`。
- 验票成功，记录票状态。
- 管理端查询成功，记录查询结果摘要。

### 3. 失败请求记录

例如：

- 重复验票失败，会记录业务错误。
- 管理端密钥错误，会记录 `UNAUTHORIZED`。
- 后端服务未启动，会记录 `NETWORK_ERROR`。

```powershell
npm.cmd run build
```

预期结果：

- 构建成功。

### 后端测试

在项目根目录执行：

```powershell
mvn test
```

预期结果：

- 测试全部通过。

### 页面手动验收

启动后端：

```powershell
mvn spring-boot:run "-Dspring-boot.run.arguments=--server.port=18086"
```

启动前端：

```powershell
cd frontend
npm.cmd run dev
```

访问：

```text
http://localhost:5173
```

操作步骤：

1. 打开页面，确认活动列表加载后，最近请求记录出现“加载活动”。
2. 点击“同步抢票”，确认记录里出现 `POST /api/orders/grab`。
3. 点击“支付并出票”，确认记录里出现 `POST /api/orders/{orderId}/pay` 和刷新订单请求。
4. 点击“查询电子票”，确认记录里出现 `GET /api/tickets/{ticketCode}`。
5. 点击“验票入场”，确认记录里出现 `POST /api/tickets/verify`。
6. 重复验票一次，确认记录里出现失败记录和错误 code。
7. 把管理端密钥改错，点击“按用户查订单”，确认记录里出现 `UNAUTHORIZED`。

## 本阶段边界

本阶段暂不做：

- 请求记录持久化。
- 导出请求日志。
- 筛选和搜索请求记录。
- 对接后端日志系统。

当前先保留浏览器内存中的最近 8 条，足够支撑本地演示和排查。

## 你需要学会的点

- 接口排查不能只看页面最终状态，还要看请求轨迹。
- `traceId` 是连接前端、响应体、响应头和后端日志的线索。
- 业务失败和网络失败要区分。
- 管理端鉴权失败是 `UNAUTHORIZED`，不是系统异常。

## 面试表达

可以这样说：

> 我在前端工作台里增加了最近请求记录，每次调用接口都会记录动作、方法、路径、成功或失败、业务 code、traceId 和结果摘要。这样演示时不仅能看到订单和电子票状态，也能看到接口调用轨迹；如果出现错误，可以通过 traceId 去后端日志定位同一次请求。
