# 第 45 阶段验收：票务产品边界重构

## 目标

借鉴 12306 类票务系统的产品边界，把 EventRush 从“所有验收输出混在一页”调整为“前台票务产品 + 独立工程证据入口”。

## 交付

| 文件 | 说明 |
| --- | --- |
| `.workbench/spec.md` | 更新为票务产品与工程证据分层规格 |
| `frontend/src/App.vue` | 新增产品导航，拆分车票预订、我的电子票、验票入口和工程证据 |
| `frontend/src/style.css` | 新增产品导航、购票首页和分层入口样式 |
| `docs/stage-45-acceptance.md` | 本阶段验收说明 |

## 验收结果

| 检查项 | 结果 |
| --- | --- |
| 默认首屏 | 默认进入“车票预订”，不再先展示压测、请求记录和后台排查 |
| 产品导航 | 已拆成“车票预订 / 我的电子票 / 验票入口 / 工程证据” |
| 购票路径 | 活动票档、下单、支付出票保留在用户主流程里 |
| 电子票路径 | 查票和票据凭证从购票页拆出，独立成为“我的电子票” |
| 验票路径 | 验票员 ID 和入场核验只在“验票入口”出现 |
| 工程证据 | hook、验收摘要、traceId、请求记录、压测证据和管理排查收进独立入口 |
| 操作可达性 | 已补齐键盘焦点、移动端点击区域和横向溢出保护 |

## 本阶段边界

本阶段只调整前端产品结构和工作台规格，不改后端接口、不接入真实支付网关、不新增座位图。

## 你需要学会的点

- 产品界面和工程证明要分层，不能把用户操作、面试证据、压测表单塞在同一个首屏。
- 票务产品的默认路径应该是查票、下单、支付、出票，而不是先展示技术指标。
- 工程证据仍然重要，但它应该服务排查和讲解，不应该抢占用户路径。
