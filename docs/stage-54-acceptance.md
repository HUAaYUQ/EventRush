# Stage 54 验收：购票发现与活动详情增强

## 目标

参考大麦等真实票务平台的购买判断节奏，把购票端从“能看到活动”推进到“能判断是否值得买、怎么买、买前需要确认什么”。本阶段只服务购票用户，不引入主办方入口、验票、工程证据或压力测试。

## 做了什么

- 公开活动接口增加活动简介、封面地址和已发布公告。
- 目录支持按售票状态、地点筛选，并支持按最近场次或起售价排序。
- 活动卡片使用主办方配置的真实封面，缺失时才使用本地默认海报。
- 活动详情页增加活动介绍、购票与退改规则、活动公告。
- 详情页继续把“场次 → 票档 → 购票人 → 结算”作为唯一主路径。
- 新增后端验收：主办方发布活动和公告后，购票端能读取对应公开内容。

## 你要学会什么

- 票务首页的职责是发现和筛选，不是把下单、支付、退票全部铺开。
- 活动详情页要先解决购买判断，再承载交易动作；简介、场次、票档、规则和公告分别承担不同决策。
- 主办方输入的内容只有在活动发布后才进入公开目录，公开数据契约必须由后端状态控制。
- 真实票务产品的体验重点不是装饰，而是减少用户在时间、地点、票档、库存和退改规则上的不确定性。

## 怎么验收

1. 启动后端和前端，打开 `http://localhost:5173/`。
2. 在活动目录中使用“正在售票 / 可候补”筛选，确认结果数量会变化。
3. 使用地点筛选和“最近场次 / 起售价最低”排序，确认活动列表按真实活动数据变化。
4. 打开活动详情，确认海报、活动介绍、场次、票档、购票与退改规则正常展示。
5. 主办方发布一条公告后刷新购票端，确认详情页出现公告标题、发布时间和内容。
6. 选择场次和票档，确认仍然只能从活动详情进入结算，不会在目录卡片上直接下单。
7. 在 320px、375px、414px、768px 和桌面宽度检查筛选器、详情公告和购票按钮没有横向溢出。

## 本阶段边界

主办方订单与售后、活动延期、座位图、真实支付网关和压力测试暂不进入本阶段；工程证据继续保留独立入口，不能回流到购票导航。
