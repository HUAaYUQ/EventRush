# 第 19 阶段验收：项目 README 首页

## 本阶段交付

- 新增仓库首页文档：`README.md`。
- 汇总项目定位、核心能力、技术栈和本地启动方式。
- 补充测试命令、接口文档入口、重要目录说明。
- 补充配置开关、RocketMQ 文档入口、MySQL 建表脚本入口。
- 补充适合面试表达的项目介绍。

## 为什么要做这一阶段

GitHub 仓库首页就是项目的门面。别人打开仓库时，不会先去翻几十个阶段文档，而是先看 README。

README 要解决几个问题：

- 这个项目是什么。
- 它解决了哪些后端问题。
- 怎么启动和测试。
- API 文档在哪里。
- 项目有哪些模块。
- 面试时应该怎么介绍。

这一阶段的价值是把项目从“只有代码和阶段记录”整理成“可以展示给别人看的完整仓库”。

## 自动验收

在项目根目录执行：

```powershell
mvn test
```

预期结果：

- 测试全部通过。
- README 新增不影响业务代码。

## 手动验收

打开：

```text
README.md
```

检查以下内容：

- 是否能快速看懂 EventRush 是什么项目。
- 是否能看到本地启动命令。
- 是否能看到测试命令。
- 是否能找到 API 文档入口。
- 是否能找到 RocketMQ 和 MySQL 相关文档入口。
- 是否能看到适合面试展示的项目介绍。

## 你需要学会的点

- README 是项目的入口，不是随便写几行介绍。
- 一个后端项目的 README 至少应该包含定位、技术栈、启动方式、测试方式、接口文档和目录说明。
- 项目展示要先讲业务价值，再讲技术设计，最后讲怎么验证。
- 面试官看 README 时，最想快速判断“这个项目有没有真实后端复杂度”。

## 面试表达

可以这样说：

> 我给项目补充了完整 README，把项目定位、核心业务链路、技术栈、启动方式、测试方式、接口文档和阶段验收文档都整理到了仓库首页。这样项目不仅能运行，也能被别人快速理解和验收。
