# 第 23 阶段验收：抢票压测报告模板

## 本阶段交付

- 新增抢票压测报告模板：`docs/pressure-test-report-template.md`。
- 模板包含报告结论、压测环境、压测配置、原始输出、指标记录、现象分析、优化前后对比和面试表达。
- 在 `README.md`、`docs/learning-map.md`、`docs/pressure-test-guide.md` 中补充报告模板入口。

## 为什么要做这一阶段

第 22 阶段解决了“怎么压测”，第 23 阶段解决“压完以后怎么沉淀结果”。

压测报告的价值是：

- 把一次压测变成可展示证据。
- 让 QPS、P95、P99、成功数、失败数有地方记录。
- 让“没有超卖”能通过成功数和库存数量说明。
- 后续优化 Redis Lua 方案时，可以做前后对比。

## 手动验收

打开：

```text
docs/pressure-test-report-template.md
```

检查以下内容：

- 是否能填写压测环境。
- 是否能填写压测参数。
- 是否能粘贴脚本原始输出。
- 是否能记录 QPS、avgMs、p95Ms、p99Ms。
- 是否能分析是否超卖。
- 是否能记录优化前后对比。
- 是否有面试表达。

## 你需要学会的点

- 压测报告要先写结论，再给数据支撑。
- 抢票压测的重点不是只看吞吐量，还要验证成功数量不超过库存。
- 没有报告的压测很难在面试里作为证据。
- 优化前后要用同一套指标，否则无法公平对比。

## 面试表达

可以这样说：

> 我给抢票压测补充了报告模板，压测后可以记录环境、参数、成功数、失败数、QPS、平均耗时、P95、P99，并专门分析是否超卖和失败是否符合预期。这样压测结果不是口头描述，而是能沉淀成可展示的项目证据。
