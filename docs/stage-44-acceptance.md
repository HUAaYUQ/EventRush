# 第 44 阶段验收：前端工作台结构调整

## 目标

基于 `.workbench/spec.md` 调整前端 UI 结构，让首屏先说明本轮验收状态，再展示本轮订单证据、当前操作链路、最近请求记录和压测证据。

## 交付

| 文件 | 说明 |
| --- | --- |
| `frontend/src/App.vue` | 调整首屏摘要、模块顺序和最近请求记录展示 |
| `frontend/src/style.css` | 调整工作台首屏、证据卡、链路步骤和请求记录样式 |
| `docs/stage-44-acceptance.md` | 本阶段验收说明 |

## 验收结果

| 检查项 | 结果 |
| --- | --- |
| 首屏 hook | 已按真实订单和电子票状态动态生成，冷启动时不再提前宣称链路完成 |
| 本轮摘要 | 已展示 `userId`、`orderId`、`ticketCode`、订单状态、电子票状态和失败 `traceId` |
| 空数据提示 | 无订单和请求记录时显示 `cold_start.day_1`，不展示空表或假数据 |
| 模块顺序 | 已按“操作链路 -> 最近请求记录 -> 压测证据 -> 管理排查”调整阅读顺序 |
| 请求记录 | 已保留倒序记录，失败请求高亮，并支持复制 `traceId` |
| 压测证据 | 首屏补充是否超卖、QPS、P95、P99 和系统异常数摘要 |

## 本阶段边界

本阶段只调整前端页面结构和可读性，不改后端接口、压测脚本和第 11 阶段验收文档。

## 你需要学会的点

- 工作台首屏要先回答“本轮验收到了哪里”，再展示操作面板。
- `traceId` 不是调试细节，而是请求失败时的排查入口。
- 模块顺序要服务演示叙事：先跑链路，再看请求，再讲压测，最后做后台反查。
